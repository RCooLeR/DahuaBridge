# How The Integration Works

The integration is a Home Assistant client for DahuaBridge. It is not a Dahua device driver.

```text
Home Assistant
  -> DahuaBridge integration
  -> DahuaBridge HTTP API
  -> Dahua/NVR/IPC/VTO devices
```

## Runtime Flow

1. The config flow stores one bridge base URL.
2. Setup creates `DahuaBridgeAPI` with the Home Assistant aiohttp client session.
3. `DahuaBridgeCoordinator` polls `GET /api/v1/home-assistant/native/catalog`.
4. Platform modules inspect catalog records and add Home Assistant entities.
5. Entities read current state from the coordinator cache.
6. Buttons, switches, camera recording services, snapshots, and playback proxy requests call URLs advertised by the bridge.

The integration does not maintain its own device inventory. The bridge catalog is the source of truth.

## Main Modules

`api/`

- normalizes the configured bridge URL
- preserves direct non-HTTP targets such as `rtsp://...`
- rewrites bridge-hosted HTTP URLs through the configured base URL, including reverse-proxy path prefixes
- performs JSON, bytes, and MJPEG-frame HTTP requests

`catalog/`

- reads normalized records from the native catalog
- extracts device, state, stream, capture, intercom, controls, and features sections
- decides preferred stream profile/source order
- classifies scalar fields, binary fields, device classes, units, and diagnostic categories
- builds button and switch specs from bridge-advertised controls

`coordinator.py`

- owns polling
- decides whether stream credentials should be included in the catalog request
- exposes preferred video profile/source options to entities
- resolves the integration language from the selected option and Home Assistant language

`discovery.py`

- shares the repeated platform discovery pattern
- adds new entities when new catalog records or fields appear
- does not delete old Home Assistant registry entries

`camera.py` and `camera_support/`

- expose Home Assistant camera behavior
- fetch snapshots through bridge capture metadata first
- fall back to MJPEG frame extraction when needed
- expose stream, capture, recording, archive, profile, control, feature, and intercom attributes

`proxy/`

- parses Home Assistant timeframe camera proxy query parameters
- creates bridge playback sessions for NVR channels
- streams the selected MJPEG playback profile back to Home Assistant

## Entity Lifecycle

Entities are discovered from the current catalog and use stable unique IDs based on bridge device IDs.

When a catalog record disappears, the existing Home Assistant entity is not automatically deleted. It becomes unavailable because `DahuaBridgeEntity.record` can no longer find its backing catalog record. Remove stale entities manually from Home Assistant if a device is permanently gone.

## URL Handling

The configured bridge URL is the public URL Home Assistant should use to reach the bridge.

If the bridge returns an internal HTTP URL, the integration rewrites it to the configured bridge host and path. This makes reverse proxy deployments work:

```text
configured bridge URL: https://ha.example.com/dahuabridge
bridge catalog URL:    http://127.0.0.1:9020/api/v1/events
entity attribute URL:  https://ha.example.com/dahuabridge/api/v1/events
```

Direct `rtsp://` URLs are kept unchanged.

## Language Handling

The integration ships English and Ukrainian Home Assistant translation files.

It also has an integration language option:

- `auto`
- `en`
- `uk`

`auto` uses Home Assistant's configured language when the integration supports it. If that language is not supported, labels fall back to English.

This language is applied to names generated by the integration itself, such as:

- camera and online entity names
- normalized catalog field names
- bridge-backed button and switch names
- the `bridge_integration_language` camera attribute consumed by the Lovelace cards

Changing the option reloads the config entry so entities are recreated with the selected labels.

## Boundaries

The integration intentionally does not:

- talk directly to Dahua CGI/RPC endpoints
- own recorder configuration
- delete Home Assistant registry entries
- download recorder DAV files directly
- synthesize controls that the bridge catalog did not advertise
